Como Inicializar um Contêiner Docker com o SQL Server - Guia Completo

O Microsoft SQL Server é um dos sistemas de gerenciamento de banco de dados relacionais mais utilizados no mundo corporativo. Desenvolvido pela Microsoft, ele oferece alta performance, segurança robusta e suporte a recursos avançados como replicação, transações distribuídas, integração com ferramentas analíticas e compatibilidade nativa com o ecossistema .NET e Azure. Neste guia completo, vamos explorar duas abordagens para trabalhar com SQL Server: executando via Docker (método recomendado para desenvolvimento) e instalando diretamente no sistema operacional (para ambientes de produção ou necessidades específicas).

Por Que Usar SQL Server com Docker?

Executar o SQL Server em containers Docker oferece vantagens significativas especialmente em ambientes de desenvolvimento e testes. A principal vantagem é a portabilidade - você pode ter instâncias isoladas do SQL Server sem interferir em outras instalações ou no sistema operacional. Isso elimina o famoso problema de conflitos de versões e configurações.

A reprodutibilidade é outra vantagem crítica. Com um arquivo docker-compose.yml, toda a equipe de desenvolvimento pode ter exatamente o mesmo ambiente de banco de dados, com as mesmas versões, configurações e até mesmo dados iniciais. Não há mais aquele problema de "funciona no meu banco mas não funciona no seu".

O isolamento garante que diferentes projetos podem usar diferentes versões do SQL Server simultaneamente na mesma máquina, sem conflitos. Você pode ter um projeto usando SQL Server 2019 e outro usando SQL Server 2022, ambos rodando ao mesmo tempo em containers separados.

Por fim, a limpeza é facilitada - quando você não precisa mais de uma instância, basta remover o container. Não ficam arquivos espalhados pelo sistema, registros no Windows ou serviços rodando em background consumindo recursos.

1. Executando o SQL Server em um Contêiner Docker

A maneira mais prática e rápida de usar o SQL Server é executando-o dentro de um contêiner Docker. Esse método elimina a necessidade de instalação manual e permite isolar o banco de dados do restante do sistema. Antes de tudo, é importante garantir que o Docker esteja instalado e em execução na sua máquina.

1.1. Verificando os Pré-requisitos

Antes de iniciar, verifique se o Docker está instalado e funcionando:

# Verificar versão do Docker docker --version # Verificar se o daemon está rodando docker ps

Se esses comandos executarem sem erros, você está pronto para prosseguir. Caso contrário, consulte a documentação oficial do Docker para instalação no seu sistema operacional.

Requisitos de Hardware: O SQL Server requer no mínimo 2GB de RAM. Certifique-se de que o Docker Desktop está configurado para usar pelo menos 4GB de RAM (recomendado 8GB para melhor performance).

1.2. Iniciando com o Comando docker run

A forma mais direta de executar o SQL Server é através do comando docker run. Este método é ideal para testes rápidos ou quando você precisa de uma instância temporária:

docker run -e "ACCEPT_EULA=Y" -e "MSSQL_SA_PASSWORD=@Admin123" \ -p 1433:1433 --name sqlserver -d \ mcr.microsoft.com/mssql/server:2022-latest

Vamos entender cada parâmetro deste comando em detalhes:

  • docker run – Comando principal que cria e executa um novo contêiner a partir de uma imagem.
  • -e "ACCEPT_EULA=Y" – Variável de ambiente que aceita automaticamente o End-User License Agreement (EULA) da Microsoft. Este parâmetro é obrigatório.
  • -e "MSSQL_SA_PASSWORD=@Admin123" – Define a senha do usuário administrador do sistema (SA - System Administrator). A senha deve atender aos requisitos de complexidade do SQL Server: mínimo 8 caracteres, incluindo letras maiúsculas, minúsculas, números e símbolos.
  • -p 1433:1433 – Mapeia a porta padrão do SQL Server no contêiner (1433) para a mesma porta no host. O formato é PORTA_HOST:PORTA_CONTAINER. Isso permite que aplicações externas se conectem ao banco.
  • --name sqlserver – Atribui um nome fixo ao contêiner, facilitando comandos futuros como stop, start, logs, etc.
  • -d – Executa o contêiner em modo detached (segundo plano), liberando o terminal.
  • mcr.microsoft.com/mssql/server:2022-latest – Especifica a imagem oficial do SQL Server 2022 hospedada no Microsoft Container Registry (MCR).

1.3. Verificando o Status do Contêiner

Após executar o comando, aguarde alguns segundos para o SQL Server inicializar completamente. Você pode verificar o status com:

# Listar contêineres em execução docker ps # Visualizar logs do SQL Server docker logs sqlserver # Seguir logs em tempo real docker logs -f sqlserver

Quando o SQL Server estiver pronto, você verá mensagens como:

SQL Server is now ready for client connections. This is an informational message; no user action is required.

1.4. Requisitos de Senha do SQL Server

⚠️ Importante - Política de Senhas: O SQL Server exige senhas fortes para o usuário SA. A senha deve conter:

  • Pelo menos 8 caracteres
  • Letras maiúsculas (A-Z)
  • Letras minúsculas (a-z)
  • Números (0-9)
  • Símbolos especiais (!@#$%^&*)

Senhas que não atendem esses requisitos farão o container falhar ao iniciar.

1.5. Usando o Docker Compose (Método Recomendado)

Outra forma mais organizada e reprodutível de configurar o SQL Server é através de um arquivo docker-compose.yml. Esta abordagem é ideal para ambientes de desenvolvimento de equipe, pois permite versionar a configuração junto com o código do projeto.

Crie um arquivo chamado docker-compose.yml na raiz do seu projeto:

version: '3.8' services: sqlserver: image: mcr.microsoft.com/mssql/server:2022-latest container_name: sqlserver hostname: sqlserver ports: - "1433:1433" environment: ACCEPT_EULA: "Y" MSSQL_SA_PASSWORD: "@Admin123" MSSQL_PID: "Developer" volumes: - sqlserver_data:/var/opt/mssql - ./init-scripts:/docker-entrypoint-initdb.d restart: unless-stopped healthcheck: test: /opt/mssql-tools/bin/sqlcmd -S localhost -U sa -P "@Admin123" -Q "SELECT 1" || exit 1 interval: 10s timeout: 3s retries: 10 start_period: 10s volumes: sqlserver_data: driver: local

Detalhando cada elemento da configuração:

  • version: '3.8' – Especifica a versão do formato do Docker Compose. A versão 3.8 é estável e amplamente suportada.
  • services: – Define os serviços que serão executados. Aqui temos apenas o SQL Server, mas poderíamos adicionar outros serviços como Redis, RabbitMQ, etc.
  • image: – Indica a imagem Docker oficial do SQL Server 2022.
  • container_name: – Nome fixo do contêiner, facilitando identificação e comandos.
  • hostname: – Define o hostname interno do contêiner, útil para comunicação entre containers na mesma rede.
  • ports: – Mapeamento de portas entre host e container (HOST:CONTAINER).
  • environment: – Variáveis de ambiente para configuração do SQL Server.
  • MSSQL_PID: – Define a edição do SQL Server. Opções: Developer (gratuito), Express, Standard, Enterprise.
  • volumes: – Monta volumes para persistência de dados e scripts de inicialização.
  • restart: unless-stopped – Política de restart automático do container.
  • healthcheck: – Verifica periodicamente se o SQL Server está respondendo corretamente.

1.6. Iniciando com Docker Compose

Com o arquivo docker-compose.yml criado, execute:

# Iniciar os serviços docker compose up -d # Verificar status docker compose ps # Ver logs docker compose logs -f sqlserver # Parar os serviços docker compose down # Parar e remover volumes (apaga todos os dados!) docker compose down -v

1.7. Persistência de Dados com Volumes

Por padrão, quando um container é removido, todos os dados são perdidos. Para evitar isso, usamos volumes Docker. No exemplo acima, o volume sqlserver_data garante que seus bancos de dados, tabelas e dados permaneçam intactos mesmo se você remover e recriar o container.

Os dados ficam armazenados em:

  • Linux: /var/lib/docker/volumes/
  • Windows: \\wsl$\docker-desktop-data\data\docker\volumes\
  • macOS: ~/Library/Containers/com.docker.docker/Data/

1.8. Scripts de Inicialização

Você pode automatizar a criação de bancos de dados, tabelas e dados iniciais colocando scripts SQL na pasta init-scripts/. Crie um arquivo init-scripts/01-create-database.sql:

-- Criar banco de dados IF NOT EXISTS (SELECT name FROM sys.databases WHERE name = 'MeuBancoDeDados') BEGIN CREATE DATABASE MeuBancoDeDados; END GO USE MeuBancoDeDados; GO -- Criar tabela de exemplo IF NOT EXISTS (SELECT * FROM sys.tables WHERE name = 'Usuarios') BEGIN CREATE TABLE Usuarios ( Id INT PRIMARY KEY IDENTITY(1,1), Nome NVARCHAR(100) NOT NULL, Email NVARCHAR(100) NOT NULL, DataCriacao DATETIME DEFAULT GETDATE() ); END GO -- Inserir dados de teste INSERT INTO Usuarios (Nome, Email) VALUES ('João Silva', 'joao@email.com'), ('Maria Santos', 'maria@email.com'); GO

3. Conectando-se ao SQL Server

Depois que o contêiner estiver em execução, você pode se conectar usando diversos clientes SQL. Aqui estão as opções mais populares:

3.1. SQL Server Management Studio (SSMS)

O SSMS é a ferramenta oficial da Microsoft para gerenciar SQL Server. Disponível apenas para Windows, oferece interface gráfica completa com recursos avançados de administração, query design, debugging e profiling.

Download SSMS

Credenciais de conexão:

Server Type: Database Engine Server Name: localhost,1433 Authentication: SQL Server Authentication Login: sa Password: @Admin123

3.2. Azure Data Studio

O Azure Data Studio é uma ferramenta multiplataforma (Windows, Linux, macOS) moderna e leve, ideal para desenvolvimento. Suporta extensões, notebooks SQL e integração com Git.

Download Azure Data Studio

3.3. DBeaver

O DBeaver é um cliente SQL universal e gratuito que suporta dezenas de bancos de dados, incluindo SQL Server. Excelente para quem trabalha com múltiplos SGBDs.

Download DBeaver

3.4. Linha de Comando com sqlcmd

Você também pode se conectar diretamente via terminal usando a ferramenta sqlcmd que já vem instalada no container:

# Conectar ao SQL Server dentro do container docker exec -it sqlserver /opt/mssql-tools/bin/sqlcmd \ -S localhost -U sa -P "@Admin123" # Executar queries 1> SELECT @@VERSION; 2> GO # Listar bancos de dados 1> SELECT name FROM sys.databases; 2> GO # Sair 1> EXIT

3.5. String de Conexão para Aplicações

Para conectar suas aplicações ao SQL Server rodando no Docker, use estas connection strings:

# .NET (Entity Framework Core) Server=localhost,1433;Database=MeuBancoDeDados;User Id=sa;Password=@Admin123;TrustServerCertificate=True; # Java (JDBC) jdbc:sqlserver://localhost:1433;databaseName=MeuBancoDeDados;user=sa;password=@Admin123;encrypt=true;trustServerCertificate=true; # Python (pyodbc) Driver={ODBC Driver 18 for SQL Server};Server=localhost,1433;Database=MeuBancoDeDados;UID=sa;PWD=@Admin123;TrustServerCertificate=yes; # Node.js (mssql) { server: 'localhost', port: 1433, database: 'MeuBancoDeDados', user: 'sa', password: '@Admin123', options: { encrypt: true, trustServerCertificate: true } }

4. Instalando o SQL Server no Sistema Operacional

Embora o Docker seja a forma mais prática para desenvolvimento, há cenários onde a instalação nativa é necessária: ambientes de produção corporativos, requisitos de compliance, integração com Active Directory ou necessidade de recursos específicos do sistema operacional.

4.1. Instalação no Windows

No Windows, o método mais simples é baixar o instalador oficial no site da Microsoft. O processo de instalação é guiado por um wizard intuitivo.

Baixar SQL Server para Windows

Edições disponíveis:

  • Developer Edition: Gratuita, com todos os recursos da Enterprise Edition, mas licenciada apenas para desenvolvimento e testes.
  • Express Edition: Gratuita, ideal para pequenas aplicações. Limitada a 10GB por banco e 1GB de RAM.
  • Standard Edition: Versão comercial com recursos intermediários.
  • Enterprise Edition: Versão completa com todos os recursos corporativos.

4.2. Instalação no Linux

O SQL Server está disponível para as principais distribuições Linux: Ubuntu, Red Hat Enterprise Linux (RHEL), SUSE Linux Enterprise Server (SLES) e containers Docker.

Exemplo de instalação no Ubuntu 22.04:

# Importar chave GPG da Microsoft wget -qO- https://packages.microsoft.com/keys/microsoft.asc | sudo apt-key add - # Adicionar repositório do SQL Server sudo add-apt-repository "$(wget -qO- https://packages.microsoft.com/config/ubuntu/22.04/mssql-server-2022.list)" # Atualizar índice de pacotes sudo apt-get update # Instalar SQL Server sudo apt-get install -y mssql-server # Executar configuração inicial sudo /opt/mssql/bin/mssql-conf setup # Verificar status do serviço sudo systemctl status mssql-server

4.3. macOS

O macOS não possui suporte nativo ao SQL Server devido a limitações de arquitetura e licenciamento. No entanto, você tem três opções viáveis:

  • Docker (Recomendado): Use o método descrito no início deste guia. É a forma mais prática e funciona perfeitamente no macOS.
  • Azure SQL Database: Utilize uma instância do SQL Server na nuvem Azure. Ideal para desenvolvimento com necessidade de recursos cloud.
  • VM Windows: Execute Windows em uma máquina virtual e instale o SQL Server normalmente.

5. Gerenciamento e Manutenção

5.1. Comandos Úteis do Docker

# Parar o SQL Server docker stop sqlserver # Iniciar o SQL Server docker start sqlserver # Reiniciar o SQL Server docker restart sqlserver # Ver logs em tempo real docker logs -f sqlserver # Ver últimas 100 linhas de log docker logs --tail 100 sqlserver # Remover o container (dados em volumes são preservados) docker rm -f sqlserver # Ver uso de recursos docker stats sqlserver # Inspecionar configuração do container docker inspect sqlserver # Executar comandos dentro do container docker exec -it sqlserver bash

5.2. Backup e Restore

Fazer backup de um banco:

# Criar diretório para backups no host mkdir -p ~/sql-backups # Fazer backup docker exec sqlserver /opt/mssql-tools/bin/sqlcmd \ -S localhost -U sa -P "@Admin123" \ -Q "BACKUP DATABASE MeuBancoDeDados TO DISK = '/var/opt/mssql/data/MeuBancoDeDados.bak' WITH FORMAT, INIT" # Copiar backup do container para o host docker cp sqlserver:/var/opt/mssql/data/MeuBancoDeDados.bak ~/sql-backups/

Restaurar um banco:

# Copiar backup do host para o container docker cp ~/sql-backups/MeuBancoDeDados.bak sqlserver:/var/opt/mssql/data/ # Restaurar banco docker exec sqlserver /opt/mssql-tools/bin/sqlcmd \ -S localhost -U sa -P "@Admin123" \ -Q "RESTORE DATABASE MeuBancoDeDados FROM DISK = '/var/opt/mssql/data/MeuBancoDeDados.bak' WITH REPLACE"

6. Resolução de Problemas Comuns

6.1. Container Não Inicia

Problema: O container sqlserver para imediatamente após iniciar.

Soluções:

  • Senha fraca: Verifique se a senha atende os requisitos (8+ caracteres, maiúsculas, minúsculas, números e símbolos)
  • Memória insuficiente: Aumente a RAM disponível para o Docker (mínimo 2GB, recomendado 4GB)
  • Porta em uso: Verifique se outra aplicação está usando a porta 1433
# Verificar logs de erro docker logs sqlserver # Verificar se porta está em uso netstat -an | grep 1433 # Linux/macOS netstat -an | findstr 1433 # Windows # Testar com porta diferente docker run -e "ACCEPT_EULA=Y" -e "MSSQL_SA_PASSWORD=@Admin123" \ -p 1434:1433 --name sqlserver2 -d \ mcr.microsoft.com/mssql/server:2022-latest

6.2. Não Consegue Conectar

Problema: Aplicação não consegue conectar ao SQL Server.

Soluções:

# Verificar se container está rodando docker ps # Verificar se SQL Server está aceitando conexões docker logs sqlserver | grep "ready for client connections" # Testar conexão do host docker exec sqlserver /opt/mssql-tools/bin/sqlcmd \ -S localhost -U sa -P "@Admin123" -Q "SELECT @@VERSION" # Verificar firewall (Windows) # Permitir porta 1433 no Windows Firewall # Verificar rede Docker docker network inspect bridge

6.3. Erro de Autenticação

Problema: "Login failed for user 'sa'"

Soluções:

  • Verifique se a senha está correta (case-sensitive)
  • Adicione TrustServerCertificate=True na connection string
  • Use encrypt=true;trustServerCertificate=true em aplicações Java

6.4. Performance Baixa

Problema: Queries lentas ou timeouts frequentes.

Soluções:

# Aumentar memória disponível docker update --memory 4g --memory-swap 8g sqlserver # Verificar uso de recursos docker stats sqlserver # Otimizar configurações de memória docker exec sqlserver /opt/mssql/bin/mssql-conf set memory.memorylimitmb 3072 # Reiniciar container docker restart sqlserver

6.5. Espaço em Disco Cheio

Problema: Volume do Docker fica sem espaço.

Soluções:

# Ver uso de espaço do Docker docker system df # Limpar recursos não utilizados docker system prune -a --volumes # Fazer backup e limpar logs de transação docker exec sqlserver /opt/mssql-tools/bin/sqlcmd \ -S localhost -U sa -P "@Admin123" \ -Q "BACKUP LOG MeuBancoDeDados TO DISK = '/var/opt/mssql/data/log_backup.trn'" # Reduzir log de transação docker exec sqlserver /opt/mssql-tools/bin/sqlcmd \ -S localhost -U sa -P "@Admin123" \ -Q "DBCC SHRINKFILE (MeuBancoDeDados_log, 1)"

7. Boas Práticas de Segurança

7.1. Senhas Fortes

Nunca use senhas simples como "123456" ou "password". Para ambientes de produção, considere usar geradores de senhas e armazenar em cofres seguros como:

  • Azure Key Vault
  • AWS Secrets Manager
  • HashiCorp Vault
  • Docker Secrets (para Docker Swarm)

7.2. Não Exponha Portas Desnecessariamente

Em produção, evite expor a porta 1433 publicamente. Use redes internas do Docker:

version: '3.8' services: app: image: minha-aplicacao networks: - app-network depends_on: - sqlserver sqlserver: image: mcr.microsoft.com/mssql/server:2022-latest networks: - app-network # Sem mapeamento de porta externa! expose: - "1433" environment: ACCEPT_EULA: "Y" MSSQL_SA_PASSWORD: "@Admin123" networks: app-network: driver: bridge

7.3. Crie Usuários Específicos

Evite usar o usuário SA em aplicações. Crie usuários com permissões limitadas:

-- Criar login CREATE LOGIN app_user WITH PASSWORD = '@AppUser123'; -- Criar usuário no banco USE MeuBancoDeDados; CREATE USER app_user FOR LOGIN app_user; -- Conceder permissões mínimas GRANT SELECT, INSERT, UPDATE, DELETE ON SCHEMA::dbo TO app_user; -- Negar permissões administrativas DENY CONTROL ON DATABASE::MeuBancoDeDados TO app_user;

7.4. Habilite Criptografia

Para ambientes sensíveis, habilite TLS/SSL:

version: '3.8' services: sqlserver: image: mcr.microsoft.com/mssql/server:2022-latest environment: ACCEPT_EULA: "Y" MSSQL_SA_PASSWORD: "@Admin123" MSSQL_ENABLE_HADR: "1" MSSQL_ENCRYPT_CONNECTIONS: "true" volumes: - ./certs:/var/opt/mssql/secrets

7.5. Faça Backups Regulares

Automatize backups usando cron jobs ou scripts agendados:

#!/bin/bash # backup-sqlserver.sh BACKUP_DIR="/backups/sqlserver" DATE=$(date +%Y%m%d_%H%M%S) DATABASES=("MeuBancoDeDados" "OutroBanco") for DB in "${DATABASES[@]}"; do docker exec sqlserver /opt/mssql-tools/bin/sqlcmd \ -S localhost -U sa -P "@Admin123" \ -Q "BACKUP DATABASE $DB TO DISK = '/var/opt/mssql/data/${DB}_${DATE}.bak' WITH FORMAT, INIT" docker cp sqlserver:/var/opt/mssql/data/${DB}_${DATE}.bak $BACKUP_DIR/ done # Manter apenas últimos 7 dias de backup find $BACKUP_DIR -name "*.bak" -mtime +7 -delete

8. Monitoramento e Performance

8.1. Queries de Monitoramento

-- Verificar conexões ativas SELECT session_id, login_name, host_name, program_name, status, cpu_time, memory_usage FROM sys.dm_exec_sessions WHERE is_user_process = 1; -- Identificar queries lentas SELECT TOP 10 qs.total_elapsed_time / qs.execution_count AS avg_elapsed_time, qs.execution_count, SUBSTRING(qt.text, (qs.statement_start_offset/2)+1, ((CASE qs.statement_end_offset WHEN -1 THEN DATALENGTH(qt.text) ELSE qs.statement_end_offset END - qs.statement_start_offset)/2) + 1) AS query_text FROM sys.dm_exec_query_stats qs CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) qt ORDER BY avg_elapsed_time DESC; -- Verificar uso de CPU e memória SELECT sqlserver_start_time, (SELECT COUNT(*) FROM sys.dm_exec_sessions WHERE is_user_process = 1) AS user_connections, cpu_count, physical_memory_kb / 1024 / 1024 AS physical_memory_gb FROM sys.dm_os_sys_info; -- Ver tamanho dos bancos de dados SELECT DB_NAME(database_id) AS DatabaseName, SUM(size * 8 / 1024) AS SizeMB FROM sys.master_files GROUP BY database_id ORDER BY SizeMB DESC;

8.2. Ferramentas de Monitoramento

Para ambientes corporativos, considere usar:

  • SQL Server Profiler: Ferramenta integrada para trace de eventos
  • Extended Events: Successor do Profiler, mais leve e eficiente
  • Azure Monitor: Para SQL Server na nuvem
  • Grafana + Prometheus: Stack open source para monitoramento
  • Datadog, New Relic: Soluções comerciais completas
